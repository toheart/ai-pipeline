# 需求类测试提示词模板

适用场景：从业务需求出发做测试分层设计。读取前请先读取 `layered-testing-framework.md` 获取分层模型和 3KU 原则。

---

## 1. 需求测试分层设计

合并原文 #1（需求分层）和 #4（业务流程全栈方案）。

### 输入参数

- `requirement`：业务需求描述（用户故事、PRD 片段、功能说明）
- `architecture`：（可选）系统架构、服务依赖、技术栈
- `interfaces`：（可选）相关接口定义

### 输出要求

1. **风险分析**：主要业务风险、技术风险、集成风险
2. **分层方案**（逐层）：
   - 单元测试测什么
   - 组件/模块测试测什么
   - 集成测试测什么
   - 契约测试测什么
   - API/接口测试测什么
   - 皮下测试测什么
   - UI/E2E 测什么
   - 验收测试测什么
   - 生产巡检测什么
3. **每层选择的 3KU 理由**：Useful（有效）、Ultimate（最优层）、Unique（不重复）
4. **不值得测/不值得自动化的部分**

---

## 2. 微服务调用链测试需求识别

原文 #5。

### 输入参数

- `call_chain`：微服务调用链描述（架构图、时序图、服务列表）
- `protocols`：通信协议（REST / gRPC / MQ / 其他）

### 输出要求

1. 服务提供者和消费者清单
2. REST/RPC 接口契约、异步消息契约
3. 可控依赖（适合真实集成）vs 不可控依赖（适合 Mock）
4. 需要契约测试的接口
5. Happy Path 路径
6. 适合皮下测试的场景
7. 必须 E2E 验证的风险
8. 可放入 CI 的测试

---

## 3. Mock / 挡板策略设计

原文 #6。

### 输入参数

- `service`：当前服务名称和职责
- `dependencies`：依赖的下游服务列表及其状态（已就绪/未完成/不稳定）

### 输出要求

1. 每个依赖：Mock vs 真实集成的决策及理由
2. Mock 需模拟的正常响应和异常响应
3. 响应数据设计
4. 防止 Mock 与真实接口契约漂移的方法
5. CI 中如何使用这些 Mock
6. 后续必须补充真实集成测试的场景

---

## 4. 测试数据策略设计

原文 #15。

### 输入参数

- `business_flow`：业务流程描述
- `data_entities`：涉及的核心数据实体

### 输出要求

1. 输入数据、前置数据、链路数据、环境数据、静态数据清单
2. 每类数据的准备方式（Out-of-box / On-the-fly / API 造数 / 数据库 / Mock）
3. 数据隔离策略
4. 数据清理策略
5. CI 环境中的数据管理方案

---

## 5. 生产巡检方案设计

原文 #16。

### 输入参数

- `system`：系统描述（核心链路、部署方式、用户量级）
- `deploy_strategy`：部署策略（蓝绿/灰度/滚动）

### 输出要求

1. 适合巡检的核心链路
2. 必须避免的操作
3. 只读巡检 vs 需要测试账号的巡检
4. 巡检频率
5. 失败告警策略
6. 如何关联日志、trace id 和监控指标
7. 蓝绿/灰度发布后验证方案
